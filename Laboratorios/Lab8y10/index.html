Lab 6 - Preguntas a responder

1) ¿Por qué es una buena práctica usar JavaScript para checar que sean válidos los inputs de las formas antes de enviar los datos al servidor?

Porque mejora la experiencia del usuario: permite detectar errores de inmediato (sin recargar la pagina), reduce intentos fallidos y evita enviar solicitudes innecesarias al servidor. Tambien ayuda a filtrar errores comunes desde el cliente, aunque la validacion real debe repetirse en el servidor.

2) ¿Cómo puedes saltarte la seguridad de validaciones hechas con JavaScript?

Se puede desactivar JavaScript en el navegador, modificar el codigo desde las DevTools, alterar el HTML (por ejemplo quitar restricciones), o enviar la solicitud directamente sin usar la pagina (ej. con Postman, curl o un script). Por eso la validacion en cliente no es una medida de seguridad completa.

3) Si te puedes saltar la seguridad de las validaciones de JavaScript, entonces ¿por qué la primera pregunta dice que es una buena práctica?

Porque es buena practica por UX y eficiencia, no por seguridad. JavaScript sirve para dar retroalimentacion rapida y evitar cargas innecesarias, pero la seguridad se garantiza validando tambien en el servidor. Lo correcto es validar en ambos lados: cliente para mejorar la experiencia y servidor para proteger el sistema y los datos.
